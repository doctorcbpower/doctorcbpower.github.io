Cleaning AI Attribution from Git History

This procedure removes unwanted AI attribution, such as Co-Authored-By: Claude ..., from existing Git commit messages while preserving the rest of the history.

Important: rewriting Git history changes commit hashes. Make a backup before proceeding, and coordinate with anyone else who may have cloned the repository.

1. Check the repository before changing anything

git status
git branch --show-current
git remote -v

Identify the branch that is actually being used. Do not assume that it is main; it may be master or another branch.

2. Make a backup

Create a separate clone or branch before rewriting history. A separate mirror clone is the safest option: 

git clone --mirror <REPOSITORY-URL> repository-backup.git

Alternatively, create a local safety branch: 

git branch backup-before-history-rewrite

3. Inspect the existing history

Search commit messages for the attribution you want to remove: 

git log --all --format='%H %s%n%b' |
  grep -i -E 'claude|co-authored-by'

Adjust the search expression if the unwanted attribution uses a different name or form.

4. Rewrite the commit messages

git-filter-repo can rewrite commit messages throughout the repository. For example, to remove a Claude Co-Authored-By trailer: 

git filter-repo --force --message-callback \
'import re; message = re.sub(rb"(?im)^[ \t]*co-authored-by:[ \t]*claude[^\n]*\n?", b"", message); return message'

The regular expression is deliberately case-insensitive and removes the complete attribution line rather than altering other parts of the commit message.

For another attribution, replace claude with the appropriate identifying text and adjust the expression if necessary.

5. Verify the rewritten history

Search again: 

git log --all --format='%H %s%n%b' |
  grep -i -E 'co-authored-by.*claude'

No output means that the matching attribution is no longer present in the reachable history.

Inspect recent commits manually as well: 

git log -5 --format='%h %an <%ae>%n%B%n---'

6. Check branches, tags and repository state

git branch -a
git tag
git status

History rewriting can affect more than the branch currently checked out. Confirm that the branches and tags you intend to retain are present and that the working tree is in the expected state.

7. Reconnect to the remote if necessary

Depending on how git-filter-repo was run and the repository configuration, the remote may have been removed. Check: 

git remote -v

If necessary, restore it: 

git remote add origin <REPOSITORY-URL>

Then fetch the remote state: 

git fetch origin

8. Compare the rewritten branch with the remote

Replace BRANCH with the actual branch name: 

git log --oneline --left-right --graph origin/BRANCH...BRANCH

Because the history has been rewritten, the local commits will normally have different hashes from the old remote commits.

9. Force-push the rewritten history

Take care here. This replaces the remote history with the rewritten history. Confirm the branch name before running the command. 

git push --force origin BRANCH

Do not substitute main merely because it is conventional. Use the branch reported by git branch --show-current or the repository's actual default branch.

10. Prevent the attribution from returning

If the attribution is being added automatically by a local Git hook or another tool, remove or filter it before committing. Otherwise a clean history can acquire the same attribution again after the rewrite.

A commit-message hook can remove unwanted trailers before the commit is created. Test the hook by making a normal commit and inspecting: 

git log -1 --format='%B'

11. Final verification

Run the search one final time: 

git log --all --format='%H %s%n%b' |
  grep -i -E 'co-authored-by.*claude'

Also verify the repository state: 

git status
git branch -a
git log --oneline -5

If the attribution search returns nothing and the expected branches and commits are present, the reachable history has been cleaned.

Summary

  1. Check the current repository and branch.
  2. Make an independent backup.
  3. Search the history for the unwanted attribution.
  4. Rewrite commit messages with git-filter-repo.
  5. Verify that the attribution has disappeared.
  6. Check branches and tags.
  7. Restore the remote if necessary.
  8. Compare the rewritten branch with the remote.
  9. Force-push the correct branch.
  10. Install or retain a commit hook so the attribution does not return.
Principle: clean the existing history once, then prevent the unwanted metadata from being introduced into future commits.
